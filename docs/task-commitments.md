# Task commitments and completion assessments

Version 0.27.0 adds an observe-only record for workspace work. It does not change the STP kernel or use self-assessments to authorize completion, permissions, routing, repair or budget decisions.

The conversation router can emit `task_observation` when selecting a workspace handoff. It contains its understanding, up to six deliverables with observable completion criteria, and assumptions. The host stores the original request, model identity, contract hash, constraints, invocation ID and version alongside that interpretation. The receipt exists before workspace execution. Greetings and ordinary conversational answers have no commitment ceremony.

Fresh workspace, child-review and coding calls receive the same commitment in `conversation_handoff.task_commitment`, independently of model selection. It is unverified model context. The full current contract remains pinned separately; the router's tool-free permissions are not substituted for workspace permissions. Child assessments describe their branch only. All versions remain in immutable receipts; a routing continuation creates a new linked version rather than overwriting the earlier interpretation. New user requests have separate commitments. Workers cannot revise the saved criteria.

The worker decoder requests a self-assessment when a commitment is present; host admission still treats it as diagnostic. A worker may emit a self-assessment with a complete/partial/blocked judgement, delivered summary, remaining work, and a status/evidence statement for each criterion. Evidence statements are model claims, not verified assertions. The host records missing or duplicate criterion IDs and contradictions such as “complete” with remaining work. These observations never change the answer's existing admission checks. A malformed or absent observation is recorded as malformed/missing and does not cause a repair or another model call.

The gateway removes the diagnostic field before validating the authoritative answer or action. The original model response can still be reconstructed and checked against its hash using the separately stored diagnostic field and host metadata. A malformed main response, changed constraints or invalid action remains subject to normal validation. A self-assessment cannot hide those failures.

Native chat displays the commitment before workspace work and an Asked / Model says it delivered / Remaining summary after a worker response. Withheld responses and unexecuted action proposals are labelled independently of the model judgement. Sutra Monitor displays the latest 12 observations, including model, criterion details and issues. Gateway acceptance is not final report publication or proof that the task succeeded. No model text in these views is a command.

No separate model call is scheduled for commitments or assessments. Prompt and generated observation tokens still count toward existing context and task allocations. These fields can affect model behavior, latency and available space; existing main-answer checks may still trigger bounded repair. Observe-only means no new decision authority, not zero computational cost. Absence never fabricates a successful observation. A direct advanced call without an earlier router commitment has no precommitment. The first version does not yet add precommitment to substantive conversation-only tasks or independently judge whether the model's interpretation fully matches the original request.

Testing covers malformed/missing observations, false completion claims, unchanged action/constraint enforcement, receipt reconstruction, reload, resource-pause recovery, child inheritance, and small/large model switches without budget reset. Live trial artifacts separately report whether real models actually produced the optional observations. This mechanism does not resolve the known architecture worker/reviewer output-allocation limit.
